# 部署与运维

> 本文面向运维：怎么把它装到服务器上、日志怎么老化、出事怎么查。
> 关联：`README.md`（本地怎么跑）、`docs/04-实现说明.md`（模块与偏差）。
>
> 下文以一台 2 核 2G 的 Alibaba Cloud Linux 3（x86_64）实例为例，`<user>`、`<your-server>` 请替换成你自己的账号与地址；
> 目录按 `~/ai-game` 约定，账号需要能免密 sudo（安装 systemd 单元与 logrotate 规则那一步用）。

## 1. 目标机与目录

| 项 | 值 |
| --- | --- |
| 主机 | `<your-server>`（Alibaba Cloud Linux 3 / RHEL 系均可，内核 5.10） |
| 账号 | `<user>`（免密 sudo；Node ≥ 22，示例用 nvm 提供的 `~/.nvm/versions/node/v24.18.0`） |
| 部署目录 | `/home/<user>/ai-game`（代码 + `data/` + `logs/`） |
| 端口 | `8787`（`0.0.0.0`），同一端口同时提供前端页面、`/api` 与 `/ws` |
| 同机邻居 | 这台机器上还跑着别的服务（一个 systemd 单元 + 一个 docker 容器）。本服务沿用同一套 systemd + logrotate 风格，并用 `--max-old-space-size=1024` 给 V8 堆设上限，避免互相抢内存 |

**单进程架构**：`apps/server` 用 Fastify 同时负责 REST、观战 WebSocket 和前端静态文件
（`apps/server/src/app.ts` 末尾把 `apps/web/dist` 挂在 `/*` 并回落到 `index.html`），
所以不需要 nginx/反向代理——前端只用相对路径 `/api`、`/ws`，天然同源。

```
/home/<user>/ai-game
├─ apps/ packages/ tools/ docs/ …        # 代码（publish.sh 同步，不含 node_modules/data/logs）
├─ apps/web/dist/                        # 前端构建产物（install.sh 里 pnpm build:web 生成）
├─ data/                                 # 业务数据：ai-game.db(SQLite) + master.key + maps/*.json(自定义地图)
├─ logs/                                 # app.log（服务输出）+ maintenance.log（老化脚本上报）+ 归档 *.gz
└─ deploy/                               # 部署资产（本目录）
```

## 2. 一次部署（三步）

```bash
# ① 开发机：同步代码（不含 node_modules / data / logs）
AI_GAME_HOST=<user>@<your-server> bash deploy/publish.sh

# ② 服务器：装依赖 → 构建前端 → 装 systemd/logrotate/crontab → 启动 → 自检
ssh <user>@<your-server> 'bash ~/ai-game/deploy/install.sh'

# ③ 验证（服务器本机）
curl -s http://127.0.0.1:8787/api/health
```

> **公网访问**：服务监听的是 `0.0.0.0:8787`，能不能从公网打开取决于云厂商**安全组/防火墙**是否放行该端口
> （常见坑：SSH 与某些已部署服务的端口是放行的，新端口默认不放行）。二选一：
> ① 在云控制台给安全组加一条 `TCP 8787` 入方向规则；
> ② 不改安全组，用 SSH 隧道（改前先用这个方式验证最省事）：
>
> ```bash
> ssh -N -L 8788:127.0.0.1:8787 <user>@<your-server>     # 保持这个窗口不关
> # 浏览器打开 http://127.0.0.1:8788/  （页面里的接口地址会显示成本地映射地址，属正常）
> ```

`install.sh` 是幂等的：升级时重复执行即可（`pnpm install` → `pnpm build:web` → `systemctl restart ai-game`）。

### 2.1 首次部署时导入本地数据（可选）

服务器上 `data/` 独立存在，`publish.sh` 不会覆盖它。想把开发机上的对局一起带过去，
用 SQLite 自己在线的 `VACUUM INTO` 导出一份干净副本（不含 WAL），再传上去：

```bash
# 开发机
node -e "const {DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('data/ai-game.db');d.exec(\"VACUUM INTO 'data/ai-game.seed.db'\");d.close()"
scp data/ai-game.seed.db <user>@<your-server>:/tmp/seed.db
scp data/master.key <user>@<your-server>:/tmp/master.key
# 服务器（先停服务，或只在首次安装、data 为空时做）
ssh <user>@<your-server> 'sudo systemctl stop ai-game; install -m600 -o <user> -g <user> /tmp/master.key ~/ai-game/data/master.key; install -m644 -o <user> -g <user> /tmp/seed.db ~/ai-game/data/ai-game.db; sudo systemctl start ai-game'
```

`data/master.key` 是注册密钥的哈希主密钥：**换了它，历史 Agent 密钥全部作废**（已入库的脚本与对局不受影响）。
生产环境可以用 `~/ai-game/.env` 里的 `AI_GAME_MASTER_KEY`（64 位 hex）固定下来。

## 3. 日志老化机制（三层，互不依赖应用自身）

服务日志由 systemd 直接追加到 `logs/app.log`（不走 journald，`journalctl -u ai-game` 是空的，属正常）。

> 注意一个坑：systemd 是以 **root** 打开 `StandardOutput=append:` 的文件、然后才把进程降权到 `User=` 的，
> 所以日志文件若由 systemd 首次创建就会是 `root:root 644`——运行账号既不能截断它，logrotate 的 `su …`
> 也切不动。`install.sh` 因此会先 `touch logs/app.log`（属主 = 运行账号）再启动；手工部署时别漏这一步。

| 层 | 触发 | 规则 | 作用 |
| --- | --- | --- | --- |
| ① logrotate（系统） | `/etc/cron.daily/logrotate`，每天一次（anacron，3:00–22:00 间） | `maxsize 20M`、`rotate 14`、`compress`、`delaycompress`、`copytruncate` | 常规滚动：单文件超 20MB 即切、最多留 14 份并 gzip |
| ② crontab 兜底（每 15 分钟） | 运行账号的 crontab 跑 `deploy/log-maintenance.sh` | 见下 | logrotate 一天只醒一次，这一层保证 15 分钟内就发现问题 |
| ③ 磁盘水位（同 ②） | 同一脚本读 `df` | ≥85% 只留最近 3 份归档并压目录上限；≥92% 清空全部日志 | 最后一道闸，保证不会把分区写满 |

`deploy/log-maintenance.sh` 的行为与可调参数：

```
LIVE_MAX_MB=40    单个 *.log 超限 → 立即切档（先复制成 .gz 再清空原文件，进程不重启、不丢行）
KEEP_DAYS=14      归档保留 14 天，过期的 *.gz 直接删
DIR_MAX_MB=200    logs 目录硬上限 200MB，超了从最旧的归档开始删
WARN_PCT=85       分区使用率 ≥85%：只保留最近 3 份归档，目录上限压到 50MB
CRIT_PCT=92       分区使用率 ≥92%：清空全部日志文件（只留一行告警）
DB_WARN_MB=2048   data/ai-game.db ≥2GB 时在 maintenance.log 里记一行 WARN（只告警，不删数据）
```

改参数：直接编辑 crontab 那一行（`crontab -e`），例如 `LIVE_MAX_MB=20 DIR_MAX_MB=100 /bin/bash ~/ai-game/deploy/log-maintenance.sh`。
每 15 分钟会在 `logs/maintenance.log` 写一行状态，趋势一眼可见：

```
2026-10-19 22:31:02 ok disk=19% logs=0MB db=0MB live=4096B
```

## 4. 常用运维命令

```bash
sudo systemctl status ai-game          # 状态
sudo systemctl restart ai-game         # 重启（SIGTERM 优雅退出：先关库再关 HTTP）
tail -f ~/ai-game/logs/app.log         # 实时日志
tail -n 20 ~/ai-game/logs/maintenance.log   # 日志老化脚本的上报
ls -lh ~/ai-game/logs                  # 当前日志与归档
sudo logrotate -f -v /etc/logrotate.d/ai-game   # 手工强制跑一次轮转（验证用）
df -h /                                # 磁盘
crontab -l                             # 看定时任务
```

升级：

```bash
AI_GAME_HOST=<user>@<your-server> bash deploy/publish.sh && ssh <user>@<your-server> 'bash ~/ai-game/deploy/install.sh'
```

## 5. 数据增长（不是日志，但同样占磁盘）

`data/ai-game.db` 存 Agent、赛事、对局、回放事件流与上传的 zip，会随比赛数量增长
（一场约 100 回合的对局回放是几百 KB 级）。`log-maintenance.sh` 只上报体积、**不删业务数据**。需要瘦库时：

```bash
sudo systemctl stop ai-game
sqlite3 ~/ai-game/data/ai-game.db "DELETE FROM matches WHERE created_at < '2026-01-01T00:00:00Z';"  # 手工挑时间点
sqlite3 ~/ai-game/data/ai-game.db "VACUUM;"
# 或者直接重来：删库 + 删 master.key，服务重启后自动重建（Agent 全部作废）
sudo systemctl start ai-game
```

## 6. 安全边界（重要）

平台目前的**注册 / 删除 Agent、发起赛事、保存删除地图都没有鉴权**（单机假设，见 `docs/04` §5 待办第一条）。
`HOST=0.0.0.0` + 安全组放行 8787 之后，**任何能访问该端口的人都能注册 Agent、传脚本、删数据**。建议二选一：

1. 只在云安全组里放行你自己的办公/家庭 IP（最省事，不用改代码）；
2. 改成只监听本机，通过 SSH 隧道访问：

```bash
# 服务器：~/ai-game/.env 写入 HOST=127.0.0.1，然后重启
sudo systemctl restart ai-game
# 本地：把远端 8787 映射到本地 8787
ssh -N -L 8787:127.0.0.1:8787 <user>@<your-server>
# 然后浏览器打开 http://127.0.0.1:8787
```

另外：`AI_GAME_MAX_CONCURRENT`（默认 4）、`AI_GAME_TURN_INTERVAL_MS`（默认 1200，只影响实时观战节奏，
赛事是尽快跑完的）都可以在 `.env` 里调；2G 内存的小机器建议保留单元里 `NODE_OPTIONS=--max-old-space-size=1024`
这行——它只限制 V8 堆，沙箱内存不计入其中。

## 7. 部署资产清单（`deploy/`）

| 文件 | 装到哪 | 作用 |
| --- | --- | --- |
| `publish.sh` | 开发机执行 | 打包同步代码到远端 `~/ai-game`（排除 `node_modules`/`data`/`logs`）；地址由 `AI_GAME_HOST=<user>@<host>` 给出 |
| `install.sh` | 服务器执行 | 幂等安装：pnpm 依赖 → 前端构建 → systemd 单元 → logrotate 规则 → crontab → 启动自检 |
| `ai-game.service` | `/etc/systemd/system/ai-game.service` | systemd 单元（`Restart=always`，日志追加到 `logs/app.log`） |
| `logrotate.ai-game` | `/etc/logrotate.d/ai-game` | 第一层日志老化规则 |
| `log-maintenance.sh` | 保持仓库内，由 crontab 调用 | 第二/三层：15 分钟兜底 + 磁盘水位保护 |
