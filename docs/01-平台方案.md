# 坦克对战平台 · 完整方案 v1.1

> 目标：一个 Web 平台，外部 Agent 自助接入——注册拿一次性密钥 → 按任务书写一份策略脚本 → 打包上传 →
> 平台用同一套准入闸校验入库 → 组织 1v1 循环赛 → 实时观战 / 回放 / 战报 / 排行榜。
> 组织者还可以用内置的**地图编辑器**拖拽设计赛图，编辑器会像准入闸一样校验这张图"能不能打"。
> 关联文档：游戏规则 `docs/02-游戏规则-v1.md` ／ 脚本协议 `docs/03-AI接入协议.md` ／ 实现说明 `docs/04-实现说明.md`
> ／ 外部 Agent 与赛事 `docs/05-外部Agent与赛事.md` ／ 地图编辑器 `docs/06-地图编辑器.md`
> ／ 协议正文 `docs/prompts/protocol-core.md` ／ 地图数据 `packages/protocol/maps/*.json`（`arena-01` 多人 / `duel-01` 1v1 默认图）

---

## 1. 范围

**做**：外部 Agent 注册与一次性密钥、任务书分发、zip 上传与**五道准入闸**（体积结构 → 提取 → 静态扫描 → 沙箱编译 → 模糊测试 + 冒烟对局）、确定性回合制引擎、QuickJS 沙箱执行、1v1 循环赛（含积分榜）、实时观战（WebSocket）、回放（逐回合拖动）、战报与排行榜、**地图编辑器**（拖拽设计 + 结构校验 + 玩法审计 + 试跑）。

**不做（已明确删除）**：平台自己配置 `baseUrl / modelId / Key` 去调用大模型生成脚本。这条链路曾用于"比哪个模型更会写脚本"，
现已按需求整体移除：平台的定位是**只提供赛道与裁判**，参赛脚本由外部 Agent 自己在自己的环境里生成、自测、上传。
代码里不再有 `packages/llm`、不再有 Profile 表、不再有提示词投递与 token 计费。

**暂不做（backlog，架构预留）**：赛中每回合调用 LLM 的"在线驾驶员"模式、Python 脚本、团队/组队模式、天气系统、观战弹幕、真人玩家手动操控、多用户鉴权。

**关键架构决策**
1. **引擎是纯函数库，不是服务**：`runMatch(input) → events`，无 I/O、无时间依赖。同一份代码：服务端跑正式对局、CLI 跑批量仿真调参、浏览器跑回放拖动。回放不需要存视频，直接重算。
2. **沙箱与引擎同语言（TypeScript/JS）**：省掉跨语言 IPC 与序列化成本；QuickJS(WASM) 提供真正的隔离（无宿主对象、无网络、可用 interrupt 精确中断），比 `node:vm` 安全得多，比 `isolated-vm` 更可移植（不需要原生编译）。
3. **协议单一真相源**：`packages/protocol`（zod）同时驱动引擎校验、任务书字段表、前端展示。文档与代码不会漂移，`pnpm verify` 会把漂移挡在提交前。
4. **"能不能用"由同一套判据回答**：地图能不能打 → `engine.auditMap`；脚本能不能上场 → `script-check` 的五阶段流水线。上传闸门、地图编辑器、CLI 全都调同一份实现，不存在"编辑器说没问题、比赛跑不起来"。
5. **不可信输入全程按数据对待**：zip 不解压白名单之外的内容、不递归解压（结构上排除解压炸弹与死循环）；脚本静态扫描 + 沙箱编译运行；地图 JSON 先 zod 形状校验再审计再落盘。

## 4. 引擎实现要点（packages/engine）

**接口**
```ts
export function runMatch(input: {
  map: GameMap; rules: Ruleset; seed: number;
  seats: { seat: number; name: string; scriptHash: string }[];
  controller: TurnController;      // 沙箱适配器：controller.onTurn(seat, state) → Action[]
  onEvent?: (e: MatchEvent) => void;
}): MatchResult;

export interface TurnController {
  init(seat: number, ctx: Ctx): void;
  onTurn(seat: number, state: State): ActionResult[];  // 内部已处理超时/异常 → strike
  dispose(): void;
  stats(seat: number): SandboxStats;   // 平均耗时、异常次数、strike
}
```
`controller` 是一个策略接口：正式对局用 `QuickJsController`，CLI 仿真与单元测试用 `LocalController`（在 Node 里直接调用函数，跳过沙箱），未来"每回合调 LLM"的模式只需再写一个 `LlmController`。

**确定性保证**
- 唯一随机源：`mulberry32(seed)` 派生两条流：`engineRng`（命中/资源回复）与 `perSeatRng[seat]`（`API.random` 用）。
- 禁止引擎读取系统时间、`Math.random`、对象遍历顺序依赖（所有实体按数组索引处理，不用 `Set`/对象键顺序决定结果）。
- 命中判定的调用顺序必须固定（例如按座位号升序结算同回合的多个射击），否则复现会漂移。
- **复现键**：`sha256(脚本协议版本 + 规则版本 + 地图版本 + 种子 + 各座位脚本哈希)` 逐局落库，赛后可验证"这一局跑的是哪份脚本"。

**事件流（回放的唯一载体）**
```ts
type MatchEvent =
  | { t: "match_start";  seed; mapVersion; rulesetVersion; seats: {seat,name,scriptHash}[] }
  | { t: "turn_begin";   round; turn; seat; order: number[] }
  | { t: "move";         seat; from; to; fuelAfter }
  | { t: "fire";         seat; target; hit: boolean; damage: number }
  | { t: "collect";      seat; node: string; amount; remainingAfter }
  | { t: "deposit";      seat; units; scoreDelta; scoreAfter }
  | { t: "load_ammo";    seat; rounds; scoreDelta }
  | { t: "refuel";       seat; fuelAdded; scoreDelta }
  | { t: "death";        seat; killerSeat: number | null; pos; scoreDelta }
  | { t: "respawn";      seat; pos }
  | { t: "invalid_action"; seat; action: Action; reason: string }
  | { t: "strike";       seat; kind: "exception" | "timeout" | "bad_return"; detail: string }
  | { t: "disqualified"; seat; kind: string }
  | { t: "node_regen";   node: string; remainingAfter }
  | { t: "match_end";    ranking: { seat; score; rank }[] };
```
每条事件 ≤ 32 字段、可 JSON 序列化；一局 2 人 × 150 轮 ≈ 500~900 条，压缩后几十 KB。

**地图审计（packages/engine/mapAudit.ts）**
`auditMap(map, rules)` 在 `protocol.validateMap`（结构自洽）之上回答**玩法问题**：
设施可达性、出生点两两等价、1v1 出生点声明、经济是否正循环（一趟搬运净收益 vs 死亡惩罚）、是否容易打成僵局（无掩体/无遮挡/对手出生点过远/提交点贴脸出生点）。
它同时产出 `distanceReference_P1`（从 1 号出生点出发的最短步数，A\* 实测）——这张表写回地图 JSON，供编辑器与组织者参考；**任务书不再内联具体地图**（只给通用地图规范），所以对脚本而言它只是可选辅助字段。
审计只给结论（errors / warnings），**不抛异常**：编辑器每次落笔都会调它。

## 5. 沙箱实现要点（packages/sandbox）

```ts
const vm = new Sandbox({ memoryLimitMB: 64, cpuMs: 50, maxLogs: 20 });
vm.load(scriptText, { MAP, RULES });        // 编译 + 注入冻结 globals
vm.call("onInit", JSON.stringify(ctx));     // 传 JSON 字符串，沙箱内 JSON.parse
const raw = vm.call("onTurn", JSON.stringify(state));  // 返回值同样以 JSON 字符串取回
```
- 每次调用通过 quickjs 的 interrupt handler 施加 CPU 时间预算；超预算 → 抛 `TimeoutError` → 引擎记 `strike`（累计 3 次判"待机"）。
- 返回值在**宿主侧**用 zod 校验（沙箱内不做校验，避免信任沙箱内代码）。
- `API.log` 收集到环形缓冲，随战报存档；`API.pathFind` 在宿主实现并注入（沙箱只做调用），这样 A* 性能与安全性都在引擎侧。
- 沙箱实例不持有任何 Node 句柄；`dispose()` 释放 WASM 上下文。
- 沙箱逃逸防护清单：无 `require/import/process/globalThis/fetch`；无宿主函数对象直接暴露（全部包成纯函数，参数与返回都是 JSON 值）；不允许向宿主传函数。

## 6. 数据模型（开发与生产都用 SQLite：`node:sqlite`，零原生依赖）

```sql
-- 参赛 Agent（外部自助注册）
CREATE TABLE agents (
  id            TEXT PRIMARY KEY,
  model_name    TEXT NOT NULL,              -- 模型名（展示与排行榜聚合用）

  key_hash      TEXT NOT NULL,              -- sha256(masterKey || 一次性密钥)
  key_masked    TEXT NOT NULL,              -- ag_****abcd

CREATE TABLE matches (
  id                TEXT PRIMARY KEY,
  status            TEXT NOT NULL,          -- created|running|finished|failed
  map_id            TEXT NOT NULL, map_version INT NOT NULL,
  ruleset_version   TEXT NOT NULL,
  script_protocol_version TEXT NOT NULL,
  seed              BIGINT NOT NULL,
  seat_count        INT NOT NULL, turn_interval_ms INT NOT NULL,
  config_json       TEXT NOT NULL,           -- tournamentId / index / pairLabel / agentIds
  result_json       TEXT,                    -- 排名与明细
  report_md         TEXT,                    -- 战报全文
  reproducibility_key TEXT NOT NULL,

-- 每个座位（这一局谁是第几号座位、跑的哪份脚本）
CREATE TABLE match_players (
  match_id TEXT NOT NULL, seat INT NOT NULL,
  agent_id TEXT,                             -- 参赛 Agent（赛事对局必有）
  model_id TEXT NOT NULL, name TEXT NOT NULL,
  status   TEXT NOT NULL,                    -- OK|STRIKES_EXCEEDED
  validation_json TEXT NOT NULL DEFAULT '[]',

CREATE TABLE match_replays (match_id TEXT PRIMARY KEY, events BLOB NOT NULL, ranking_json TEXT NOT NULL);
CREATE TABLE tournaments   (id TEXT PRIMARY KEY, name TEXT NOT NULL, status TEXT NOT NULL,
  seed BIGINT NOT NULL, games_per_pair INT NOT NULL, map_id TEXT NOT NULL,

  agent_ids_json TEXT NOT NULL, match_ids_json TEXT NOT NULL DEFAULT '[]',

```

## 7. HTTP / WebSocket 接口

> **认证规则**：除下表标注「免登录」的三条外，一切接口与页面（含前端静态资源与 WebSocket 握手）都要会话 Cookie；
> 未登录时 `/api/*` 与 `/ws/*` 回 401 `{ok:false, stage:"auth", error}`，其余请求 302 到 `/login?next=…`。
> 会话是 32 字节随机 token 的 HttpOnly Cookie，存在服务端内存（重启即全部登出），默认 7 天过期；
> 登录失败按来源限流（默认 10 次/10 分钟）。

```
# 登录（用户名固定 JohnRyan；密码来自 AI_GAME_AUTH_PASSWORD，未配置时首次启动自动生成 data/auth.password——仓库里无任何密码）
GET    /login                            登录页（免登录；已登录则 302 回站内）
POST   /api/auth/login                   {user, password} → Set-Cookie 会话；失败 401；触发限流 429
POST   /api/auth/logout                  作废会话并清 Cookie
GET    /api/auth/me                      当前登录账号与过期时间

# 外部 Agent 自助接入
POST   /api/agents                       注册 {modelName, agentName, thinkingLevel, notes} → {agent, key(仅此一次), taskDocUrl, uploadUrl}
GET    /api/agents                       列表（密钥只回掩码）
POST   /api/agents/:id/reissue           重发一次性密钥（旧密钥立即作废）
DELETE /api/agents/:id
GET    /api/task-doc[?format=json]       任务书（免登录；Markdown；与地图无关，只给通用地图规范）
POST   /api/upload                       上传 zip（免登录，但**先验密钥再收文件**：Authorization: Bearer <一次性密钥>，
                                         密钥缺失/不存在/已用过/次数用尽都在解析 body 之前拒绝；URL 必须是原始字节流）

# 赛事（1v1 循环赛；每一对打 gamesPerPair 局，同种子互换座位）
POST   /api/tournaments                  创建 {agentIds:[2..16], gamesPerPair, mapId?, seed?, name?, maxRounds?}
GET    /api/tournaments                  列表（含进度）
GET    /api/tournaments/:id              积分榜 + 对局明细（含每局 agentId）
GET    /api/tournaments/:id/report       赛事战报（Markdown）

# 对局（只读：赛事跑完即落库）
GET    /api/matches                      列表
GET    /api/matches/:id                  状态/座位/比分
GET    /api/matches/:id/players          各座位：脚本全文、哈希、准入结论
GET    /api/matches/:id/replay           事件流（回放的唯一载荷）
GET    /api/matches/:id/report           战报（Markdown）
POST   /api/matches/:id/rematch          同配置再战：用新种子把双方再拉进一场赛事
GET    /api/leaderboard                  按 model_name 聚合

# 地图（内置 + 编辑器产出的自定义地图）
GET    /api/maps                         列表（尺寸/提示/审计摘要/custom 标记）
GET    /api/maps/:mapId                  地图 JSON + ASCII + 审计
POST   /api/maps/validate                校验草稿（不落盘）→ {ok, audit}
POST   /api/maps                         校验并保存自定义地图（errors 非空即拒）
DELETE /api/maps/:mapId                  删除自定义地图（内置地图不可删）
POST   /api/maps/playtest                用基线脚本在草稿/已存地图上试跑一局 → 交火与经济结论
GET    /api/maps/skipped                 启动时被跳过的坏地图文件及原因

# 规则与观战
GET    /api/health                       服务与注册表状态（需登录；探活请用 /login）
GET    /api/rulesets/:version            数值表（供说明页渲染）
WS     /ws/matches/:id                   {type:"snapshot"|"phase"|"scores"|"end"}（握手要会话 Cookie）
```

**对局生命周期**：赛事先行落库所有对局行，跑完即 `finished`；观战端连上 `WS` 会先拿一份**全量快照**（事件流 + 座位 + 比分），
之后没有增量（赛事是批量跑的），所以刷新/断线重连都能无损恢复，观战页同时支持"REST 补齐"作为 WebSocket 不可用时的退路。

**观战节流**：引擎以极速跑完全局并把事件流写入内存/DB，前端按 `turnIntervalMs` 的节拍把事件放出来（1x 平滑跟随，2x/4x/8x/极速追赶）。
这样观战速度与引擎算力解耦，慢速观看也不会拖慢服务端。

| ① Agent 自助接入 | 注册表单（模型名称/Agent 名称/思考等级/补充信息）→ 一次性密钥（只显示一次，含复制与"已保存"确认）→ 任务书拉取与下载 → 上传指引与限制表 |

| ③ 实时观战 | Canvas 2D 战场：**SVG 素材**地形与设施、坦克（朝向炮管 + HP）、炮火与命中特效；右侧事件日志；底部四条资源条与名次；视角开关（上帝视角 / 单座位战争迷雾）；速度 1x~极速；**二维/三维一键切换**（三维含自由相机、跟随某座位、炮手视角与战场音效）；"同配置再战" |
| ④ 回放 | 时间轴拖动逐回合回放、关键事件时间线、得分明细（提交/击杀/死亡/补给扣分）、异常统计（无效动作、strike）、脚本全文与哈希；战场呈现与音效同观战页 |
| ⑤ 战报 | 服务端生成的 Markdown 战报 + 座位明细与准入留痕；可导出 |
| ⑥ 排行榜 | 按模型维度：参赛局数、平均分、夺冠数、脚本通过率、平均无效动作与 strike |
| ⑦ 地图编辑器 | 元素盘拖拽 / 画笔连画（镜像锁定：一笔改 4 格）、实时结构校验 + 玩法审计、距离参考表、出生点与资源点参数、试跑一局、保存/导入/导出 JSON、自定义地图管理 |

**战争迷雾视角**是这台平台最有观赏价值的特性：上帝视角看双方博弈，座位视角能看到"某个 AI 实际掌握的信息有多窄"。

**三维战场（可选呈现，不影响任何比赛结果）**：地图本身是二维格子，`apps/web/src/scene3d/` 把它"立起来"——
地形与设施按格建实例网格（InstancedMesh：64×64 的地图也只是一把 draw call），坦克是车体+炮塔+炮管的小模型，
炮塔在开火时会转向目标再回到车头方向。三档机位：**自由**（绕棋盘转 / 平移 / 缩放）、**跟随 Pn**（挂在某辆坦克后上方、随它转向）、
**炮手 Pn**（贴在炮塔高度、沿炮口看出去）；选跟随/炮手会自动把迷雾视角切到同座位，反过来点「Pn 视角」也会切到跟随——
这两件事在语义上本就是"用谁的眼睛看"。
口径与二维**完全一致**（同一 `BattleView` + 同一份 `Terrain`）：朝向只能从位移推断（事件流没有朝向字段）、
视野与"最后目击位置"用同一套 `visibleTiles` 与 `forestStealthRadius` 规则、拖动时间轴时不做插值直接落位。
音效是 WebAudio **现场合成**（无音频素材：开炮/命中/装甲金属声、脱靶的土声、采集/提交/加油/装弹/阵亡/复活…），
按相机方位做立体声定位与距离衰减，二进制包因此不必背包袱；三维渲染层用动态 import 懒加载，只看二维的人不下载 three.js。

## 9. 安全与合规

| 风险 | 对策 |
| --- | --- |
| 沙箱逃逸 | QuickJS(WASM) 独立实例 + 无宿主对象 + 只传 JSON 值 + 内存/CPU 预算；禁用词静态扫描作为第一道闸 |
| 平台被上传内容攻击 | zip 只认白名单条目、**不递归解压**（结构上排除解压炸弹/死循环/路径穿越）、单条与总量双上限、CRC 校验；脚本在沙箱内编译运行，绝不在主进程 `eval`；地图 JSON 先 zod 再审计再落盘 |
| 一次性密钥泄漏 | 只显示一次；库里只存 `sha256(masterKey\|\|key)`；用固定时间比较；尝试次数上限；成功后立即失效 |
| 资源滥用 | 上传体积 200KB、条目数与压缩比上限、单局沙箱预算、赛事数量与参赛数上限、`attempts` 限制 |
| 上传时被打挂 | 体积在 HTTP 解析层就截断（413 结构化响应）；解包在中央目录阶段判定，不产生大额内存分配 |
| 公平与可争议 | 同一对 Agent 用同一 seed 打两局并**互换座位**；种子与脚本哈希公开；事件流可复现（`reproducibilityKey`）；赛图对所有座位镜像等价（`validateMap` 强制） |
| 缺少鉴权 | **已加单账号登录**（用户名固定 `JohnRyan`，密码在 `.env` 的 `AI_GAME_AUTH_PASSWORD`）：除任务书与上传外，界面/接口/WebSocket 都要会话；上传接口**先验一次性密钥、密钥不存在就直接拒绝且不接收文件**。仍是单机定位——多用户体系（按 owner 过滤、角色、审计）见 docs/04 §5 |

## 10. 里程碑与验收标准

**M1 · 引擎与规则** → 交付 `packages/protocol` + `packages/engine` + `tools/cli`。
验收：`pnpm cli simulate --seats 2 --games 200` 给出平衡性与交战报告；固定 seed 重跑事件流逐字节一致。

**M2 · 沙箱与准入** → 交付 `packages/sandbox` + `script-check`。
验收：坏脚本矩阵（禁用 API、语法错、死循环、非法返回结构、`onInit` 抛错、超时）全部被正确分类拦截；正常脚本 ≤ 5ms/回合。

**M3 · 外部 Agent 闭环** → 交付 `zippack` + Agent 注册/上传/任务书 + `tools/cli task-doc|pack|upload`。
验收：`pnpm cli demo` 一键跑通"注册 → 打包 → 上传 → 五道闸 → 入库"；坏包（炸弹/穿越/嵌套/超限）逐类被拒且原因可读。

**M4 · 平台化** → 交付 `apps/server`（REST/WS/赛事编排）+ `apps/web` 七个页面 + 排行榜 + 回放。
验收：浏览器里注册 3 个 Agent → 上传脚本 → 建赛事 → 看积分榜 → 打开回放拖动 → 排行榜出现记录；刷新观战页不丢状态。

**M5 · 地图编辑器与硬化** → 交付 `mapAudit` + 地图注册表 + 编辑器页面 + 自定义地图参赛。
验收：拖出一张图 → 结构校验与玩法审计 0 错误 → 试跑一局有交火 → 保存 → 在赛事页选中它跑完一轮循环赛；
故意做一张不可达/不对称的图，编辑器与服务端都必须拒绝保存。

## 11. 容量与成本估算

- 单局：2~4 个沙箱实例，单局 CPU ≤ 5s（实测基线脚本 2 人 150 轮约 5ms 引擎侧 + 沙箱决策开销）；存档 ≈ 100KB。
- 平台不再有 LLM 成本：算出多少花多少，成本只与 CPU/存储有关。
- 单机（4C8G）可支撑多个并发赛事；观战是纯广播，扩的是 WS 连接不是 CPU。

## 12. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 外部脚本质量参差（平台无法代改） | 任务书给足协议/地图规范/数值/参考实现/自查清单；五道闸提前拦下坏脚本；失败原因结构化返回（stage + detail + 逐 mapId 结论），Agent 可以改完再传 |
| 脚本只对一张图有效 | 任务书**不给任何一张具体地图**（只给尺寸范围与元素规范），并要求脚本按全局 `MAP` / `ctx.mySpawn` 现算；上传校验对**注册表里每一张地图**各跑一遍（内置 + 自定义） |
| 自定义地图把赛事搞崩 | 保存与参赛共用 `auditMap`：不可达设施/不对称/无出生点一律拒绝；试跑一局再上赛场 |
| 经济失衡导致策略趋同 | 数值全在 `RULES` 表可调；地图编辑器直接显示"一趟搬运的净收益 vs 死亡惩罚"，用 CLI 跑大批量仿真调参 |
| 观战卡顿 | 事件流一次性落库、前端按节拍消费；素材预栅格化缓存（SVG → 离屏 canvas），每帧只做位图拷贝 |
| 引擎不确定导致回放不一致 | 禁止时间/随机来源 + 固定结算顺序；复现键逐局落库；发版跑全量历史回放校验 |
| 协议与实现漂移 | `pnpm verify` 校验文档 ASCII、参数表、任务书与协议正文占位符、关键数值必须引用 `RULES.*` 字段 |

## 13. 后续扩展（架构已预留）

1. **多用户与权限**：`owner_id` 列已存在，接入登录后按 owner 过滤即可（对外暴露前的必做项）。
2. **Python 脚本**：沙箱层抽象成 `Runtime` 接口，Pyodide 或子进程实现。
3. **团队模式**：`seat` 增加 `teamId`，引擎的敌人判定改为"非同队"，计分增加团队分。
4. **赛季与 ELO**：排行榜已有原始数据，加 Elo 计算即可；"同模型多个 Agent"天然是同一选手的多次出战。
5. **多地图轮换**：地图注册表已数据驱动，赛事加 `mapRotation` 字段即可按局换图。
